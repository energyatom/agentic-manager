- (decision) Form factor: desktop-class window, single user, loopback. Browser mode (Chrome/Safari/Firefox/Edge) ships first, Tauri desktop shell wraps the same web UI later. macOS Apple Silicon first; Windows 11 and Linux x64 follow. No mobile surface (PRD non-goal). Minimum supported window 1024x700; designed at 1440x900.
- (decision) UI system: React + TypeScript with Radix-style accessible primitives (brief §10 preferred, D4 keeps React UI). DESIGN.md defines its own token set (not shadcn defaults) because the Apple-calm brief needs system font, one accent and macOS-like materials.
- (decision) Owner's five guides bind UX: 1 user friendly, 2 aesthetic (Apple-grade calm: SF Pro/system font, one accent colour, 8px grid, 150-220ms causal motion, light+dark, Things/Linear density), 3 trustworthy (cost always visible, estimate vs actual, approvals show exact payload), 4 safe/secure (visible Stop everything, what-this-seat-can-touch panel, untrusted-content marking, privilege-widening confirmations), 5 comprehensive.
- (decision) Navigation: left sidebar (Org, Inbox, Runs, Workflows, Tables, Dashboards, Models & Costs, Settings/Doctor), toolbar on top with company name + cost meter pill + Stop everything + Assistant button. Org is home. ⌘K command palette, ⌘J Assistant slide-over. Seat/step/row editing in right side sheets; at most one sheet plus one confirm dialog stacked.
- (decision) Org chart is a top-down tree: reporting lines solid and vertical; grants are faint dotted lines between team boxes, shown only on hover/selection of a team and labelled with what is shared (D1). Default view collapsed (teams). Human seats render with avatar, 'You' badge and hat chip. Never a node graph and never an agents-row/tasks-row split (rejects CrewAI canvas layout).
- (decision) Workflows are NOT drawn on the org chart. The Workflow editor is a vertical step list where each step names its seat (avatar chip) inline, so 'who does what' reads top-to-bottom in one column — the fix for the CrewAI two-row wiring.
- (decision) Live cost meter: pill beside company name in the toolbar. At rest a thin ring + '₹96 / ₹600 this week'; while running it ticks with tabular figures, visual change throttled to ~1 Hz; amber at 80%; at 100% red-free 'Stopped at budget' state with Inbox ask. Per-seat spend is a secondary line on expanded seat cards only (D2).
- (decision) Estimate is always a range with basis, inline under the Run button, never a modal: 'About ₹70–150 · rough, no history' then 'About ₹80–120 · your last 4 runs'. After a run: 'Estimate ₹80–120 · Actual ₹96'. Local calls show tokens + time and ₹0.
- (decision) Stop everything is a persistent toolbar button (not hidden in a menu), neutral at rest, with a confirm-free hold-or-click: one click opens a compact confirm popover ('Stop all runs and pause all schedules?' Return confirms) — chosen so an accidental click cannot wipe a run, but stopping is still 2 keystrokes. Resume is a separate explicit action per schedule.
- (decision) Seat side sheet sections in order: Header (name, role, occupant, status) · Instructions · Model (Account › Model picker, capability chips known/tested, Test this model, Fallback) · Tools (drag from library or keyboard Add) · Budget · Drop folder · Memory notes · What this seat can touch (always visible, not behind More) · More (temperature, max tokens, output schema). Advanced params behind More per progressive disclosure.
- (decision) Account › Model picker is one grouped menu: groups are Accounts (LM Studio 'On this Mac', Ollama 'On this Mac', Anthropic, OpenAI). Each row: model name + capability chips (Tools, Structured output, Context 32k, '₹ per 1M' or 'Free (local)'), chip marked 'known' (hollow) or 'tested' (filled check). 'Recommended for Researcher' tag on one row. Warnings inline in words, never block (D3).
- (decision) Approvals show the exact payload verbatim in a monospace well (tool name, host, full arguments) before Approve. Return approves only when focus is in the Inbox item; Esc closes; never a global auto-approve. Per-action 'always allow' with undo is NOT in v1 (RULE-3 no global auto-approve; only per-proposal approval).
- (decision) Untrusted content in run drill-down: every tool result or document chunk that came from web, file, MCP or row free-text is rendered inside a hatched-edge 'Untrusted · from <source>' well, plain text only (no links rendered live, no images). Instructions are never shown inside that well.
- (decision) Privilege-widening (new tool, MCP server, bigger budget, new egress host) uses a two-step confirmation: proposal card flagged 'High risk' with a plain-language effect line, Apply opens a second confirm sheet restating the effect and requiring a typed or explicit second click on a differently-placed button.
- (decision) Inbox: list-detail split. Top of list is the 'While you were away' digest card (since last open). Item kinds: Approval, Review (gate), Draft, Question, Budget ask, Failure. 'Ask Chief of Staff' box pinned at the bottom of the list column.
- (decision) Assistant slide-over (⌘J) from the right, 400px, over any surface. Answers show the query (collapsible SQL), cite rows/runs as chips. Changes arrive as proposal diff cards (Apply / Edit / Dismiss). 'Run now' proposals show the estimate range. High-risk flag on privilege-widening proposals.
- (decision) Tables: spreadsheet grid with sticky header, saved-view tabs ([removed] view is default for [removed]), status pill + reason column, provenance shown as a small seat avatar + run link per row and in row detail history. Import/Export (CSV, xlsx) in the table toolbar; import shows a diff preview before apply.
- (decision) Dashboards: grid of Assistant-built cards (KPI, chart, small table). Each card shows its query on flip/info and 'refreshed on open'. Building a card happens only in the Assistant; dashboard page has 'Ask the Assistant for a card' as its single action. No BI editor.
- (decision) Config history: every config edit lands in a History list (Settings › History and per-seat History tab) with diff and one-step Undo. A toast 'Changed [removed]'s model. Undo' appears for 6s after each UI edit (⌘Z also undoes).
- (decision) Motion: 150–220ms ease-out, causal only: sheets slide from the edge they belong to, Inbox items arrive from the toolbar meter direction, running seat status dot pulses at 1 Hz. Reduced motion: pulses become static dot, slides become 0ms cross-fades.
