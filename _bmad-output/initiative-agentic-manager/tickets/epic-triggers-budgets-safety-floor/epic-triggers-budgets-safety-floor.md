# Triggers, inputs, budgets and safety floor (v0.1)

## Description

Our own scheduler loop with persisted state, sleep/wake catch-up and one active run per workflow; manual starts from the CLI and API with origin-specific caps; drop folders with claim-before-parse, the capped `agentic __extract` child and WorkspacePath; reserve-then-settle caps across every scope with Budget asks and schedule pauses; Stop everything as one cancellation tree with a persisted flag; untrusted-content taint, reader/actor separation, action classes and exact-payload approvals in ToolGate; department and template export and import as a Proposal with a diff, applied only by a Human command. This epic builds the one Proposal shape and its confirm token that epics 5 to 10 reuse, the tool-class registry (including `propose_change`, local-write, built out in epic 10), the injection pack that epics 8, 9 and 10 extend, and the nightly fuzzing that epic 11 makes a release gate. The golden run on the fake provider and one real local model, plus the injection pack, gate the v0.1 tag.

## Outcome

The owner leaves the owner's own departments running on their schedules and event triggers beside Paperclip, sure they cannot overspend, act on poisoned input — even input carried across a department — loop one workflow into another forever, or keep running after Stop.

## Requirements

- R1 (parent R17; arch AD-18, AD-19; ux Schedule picker): A workflow's trigger fires from our own scheduler loop over croner and jiff through the Clock port, ticking at most every 30 s, with each trigger's next fire, last fired and state (active, or paused with reason stop, budget, owner or invalid-config) persisted; scheduled runs record origin scheduled; a fire while the workflow has an active run is skipped and logged; the core reads every trigger back in words ("Every Tuesday at 08:00 · if the Mac was asleep, run once on wake", in the company timezone) for the CLI and the API.
- R2 (parent R17; arch AD-18): A wall-clock jump across fire times (sleep and wake) is detected and missed fires follow the trigger's catch-up policy from persisted state: once (default) starts exactly one run, skip starts none and logs the missed fires, all queues one run per missed fire in order; catch-up runs record origin catch-up; a paused trigger never catches up; DST follows croner's documented semantics.
- R3 (parent R18; arch AD-15, AD-19): A Human starts any workflow from `agentic run` or the API's run-start command; the run records origin manual, uses the manual caps and queues behind an active run of the same workflow.
- R4 (parent R20; parent constraint Spend caps; prd RULE-11; arch AD-9; D2): Before every model call the reservation is checked atomically against every enclosing scope (call, step, run, seat per run, week and month, workflow per run, week and month, company week), with scheduled runs held to their own lower caps; if any scope would exceed, no call is made, the step waits with a Budget ask naming the scope, spend and cap, and every schedule of the affected scope pauses with reason budget; an informational Budget item is raised once per scope and period at 80%; settled plus reserved spend against each cap is readable from `agentic status` and the API; Assistant calls (epic-assistant-dashboards) are reserved and settled as Assistant spend, with no seat or run, and count against the company week cap. Threshold: settled spend never exceeds a cap.
- R5 (parent R20; arch AD-15, AD-18): Only a Human resolves a Budget ask (Leave stopped, or Raise once for that scope and period after a second confirmation), and schedules paused for budget, stop or owner resume only by a Human command, one schedule at a time, from `agentic schedules resume` or the API; Raise once is UI class and needs the confirm token issued over the requesting UI session's live WebSocket; Leave stopped and schedule resume are CLI-class decisions, refused from the CLI while a stdio MCP server is enabled (amended 2026-11-18, final review F2). Threshold: a same-user child process holding everything in the app data dir and `.agentic/` cannot raise a cap.
- R6 (parent R21; arch AD-20; D11): Stop everything, from `agentic stop` or the API, cancels every running step at its next safe point (an in-flight stream is aborted and settles by the ledger rule), pauses every schedule with reason stop and persists a global stop flag, set through the store when no server runs, so a restart starts nothing; it reports what it stopped in words and deletes nothing.
- R7 (parent R19, R67 core; arch AD-30, AD-36, AD-39; reference-workload Parameters; restated 2026-11-18, owner connector direction): A seat's or workflow's drop folder is the watched folder of a Local Repository Source, rescanned periodically; its load run (no model) claims each file of any type by its content hash before reading it, stores text-readable files (txt, md, csv, json and a PDF's text layer) as untrusted text records and every other file as a file record, each with provenance (file, hash, load run) (restated 2026-11-19, owner folder-access direction) and records the hash in source_items, and deletes the file (default), archives or keeps it only after that load transaction committed; a consuming step reads only records new since its last successful run, through a cursor that advances in the step's commit, fenced as untrusted data naming file and hash, a file record going to the seat's model as a native file part when the model reads its type and otherwise as a worded refusal with zero bytes sent, which taints the step (rule_08 drop-folder case written to fail first with it); a file that fails stays in place with a Failure item naming the reason; a file whose hash is already claimed is skipped and logged; a claim whose load did not commit is retried once on resume.
- R8 (parent constraint Files; prd RULE-14; arch AD-30): Every file path taken by tools, parsers and imports is a WorkspacePath that is canonicalised and rejects escapes, symlinks included; the text extractor (text decoding, a PDF's text layer, sheet rows for table imports, zip expansion; no docx, pptx or OCR, restated 2026-11-19, owner folder-access direction) runs in the `agentic __extract` child with size, page, archive-expansion and time caps, and a refused or crashing parse ends in a worded error while the engine keeps running; fuzz targets for the PDF text layer, xlsx, text decoding and zip run nightly. Threshold: the path-traversal and symlink-escape suite passes.
- R9 (parent constraint Actions; prd RULE-10; arch AD-8, AD-11): Every tool manifest declares read, local-write or external-effect; ToolGate holds every external-effect call as an Approval item showing tool, host, exact arguments, size and first record; Approve once is UI class with the WebSocket-bound confirm token and runs exactly that payload, Deny (CLI or UI) returns a tool error to the step, and no always-allow exists; an external-effect call is never replayed after a restart and returns to the Inbox; no built-in v1 tool is external-effect.
- R10 (parent constraint Untrusted content; prd RULE-8; arch AD-10): Drop-folder text and rows written by a tainted step or an import reach prompts only as untrusted data; a step is tainted once any enters its context, its rows carry taint, it writes only its declared table (any other `table_write` is refused and audited), and its Approval items carry "This step read untrusted content, so it cannot use external-effect tools without your approval."; in a tainted step a read-class network call reaches only an allow-listed host and only a URL byte-identical to one recorded for the step (trusted inputs or its search results), with no model-composed path, query or body, and a search query uses only words from the step's Instruction parts; any other such call becomes an Approval showing the exact URL or query (arch AD-11, amended 2026-11-18, restoring D11 requirement 2's query-string clause). Threshold: the injection pack (poisoned PDF, docx, xlsx and table free-text, the same poison carried across a cross-department hand-off, FakeLlm scripted to obey, canary rows and lines) yields zero outbound calls, zero approvable proposals and zero requests carrying a canary in plain, URL-encoded or base64 form.
- R11 (arch AD-15; parent constraint Propose, then approve; D6): One Proposal shape carries typed config patches, an effect summary, a privilege-widening flag, source references with their taint, the config snapshot hash and an optional estimate; only a UI-class Human command applies it (the CLI lists and dismisses), through the config writer with History; apply refuses when a touched file changed since and offers to re-propose; a privilege-widening apply needs a second call with a single-use confirm token bound to that proposal and to the UI session whose live WebSocket received it, expiring after 2 minutes; Dismiss discards. Threshold: confirm-token replay, expiry, cross-proposal, cross-session, CLI-token and non-Human calls are refused.
- R12 (parent R4; arch AD-15, AD-17, AD-30; D7): A department exports as a folder or zip of its definition files only (no `.agentic/` data, no keys) and the export is refused, naming file and line, when the secret scan finds a key; a folder or zip import is unpacked under the extract caps and WorkspacePath and becomes one Proposal whose diff lists every file and, by name, every tool, MCP server, schedule and egress host it adds, and shows in full any added or changed instruction text flagged as written outside this project, which makes the import privilege-widening; nothing is applied or runs until a Human applies it, privilege-widening parts need the confirm token, and imported schedules arrive paused.
- R13 (parent constraint AI ship and rollback; arch AD-33; prd AI behavior and evaluation; parent constraint Release shape): The golden run on FakeLlm in CI and on one real local model nightly and before each tag, schema-valid at every step after at most one repair, together with the injection pack, `just check` and the RULE-8, RULE-10, RULE-11 and RULE-14 trust suites, gates the v0.1 tag; a prompt, model, instruction or memory-note change is rolled back through History Restore when SM-2 or SM-3 misses target two weeks running.
- R14 (parent R17, R21; arch AD-13, AD-32; final review UX high 3): Schedules keep firing without a terminal: `agentic service install` registers the server as a per-user macOS login item that keeps every loopback-server rule and fails closed with its reason logged, and `agentic open` makes the running server open the browser signed in with a fresh launch code it never returns to the caller; the stop flag holds under the login item; Windows and Linux CLI login items are v1.x (the desktop app covers them).
- R15 (parent R77; arch AD-44, AD-18, AD-19, AD-20; added 2026-11-18, owner REPLAN): A workflow's event trigger (`document_updated:<id>`, `step_completed:<workflow>/<step>`, `workflow_completed:<id>`, optionally only on success) is matched by the scheduler loop from committed journal events and starts a run with origin triggered, the scheduled caps and a chain context (chain id, depth, workflows already in the chain); `agentic validate` rejects any cycle in the graph of event triggers and cross-department workflow hand-offs; at run time a start past `max_chain_depth` (default 3, at most 5) or into a workflow already in the chain is refused with a Failure Inbox item and an audit entry; a running workflow queues at most one triggered run and coalesces further events; Stop everything pauses event triggers like schedules; adding an event trigger whose target is in another department is privilege-widening.
- R16 (parent constraint Child isolation; arch AD-13, AD-47; added 2026-11-19, final review 2 security H5): On macOS the parser child runs from a separately signed App Sandbox helper with no network and no access to the app data dir, projects or the keychain; a sandbox self-test at start and in Doctor makes extraction fail closed when isolation is missing, unless the owner turns on 'Run parsers without OS isolation' through the two-step confirmation. Threshold: the helper cannot open a canary in the app data dir or a project, or a socket.
- R17 (parent constraint Local server; arch AD-15; added 2026-11-19, final review 2 security H3): One exhaustive classifier decides privilege-widening for every config path and kind listed in arch AD-15, a human review gate replaced by an AI reviewer included; one confirm token may cover a listed batch; a shipped role template's own capabilities are not widening. Threshold: a property test flags every widening field identically on every path.
- R18 (parent R2, constraint Local server; arch AD-16, AD-26; added 2026-11-19, final review 2 security H4): A Reload or startup load whose snapshot widens the approved grant set is held for the two-step confirmation and nothing runs meanwhile; stdio MCP children work in `.agentic/workspace/mcp/<server-id>/`. Threshold: a same-user process editing a seat file starts zero runs before the confirmation.

## Constraints

- Propose, then approve (parent; prd RULE-3; arch AD-15, AD-28): no engine path applies a Proposal, resolves an Approval or Budget ask, resumes a schedule or raises a cap; only Human commands do, in two classes: CLI class (TTY, and only while no stdio MCP server is enabled) and UI class, with Proposal apply, Approve once and every privilege-widening decision UI class only; no always-allow.
- Generic engine (parent; prd RULE-2; arch AD-23): drop folders, caps, taint and import know no department vocabulary; the sample company reaches them only through the generic loader; event triggers name no department.
- Local and private (parent; prd RULE-5): no new network path; extraction and fuzzing are local; the egress audit is the outbound-call measure for the injection pack.
- Failing-first tests (parent; D11; arch AD-33): the RULE-8, RULE-10, RULE-11 and RULE-14 suites land here as `crates/am-e2e/tests/trust/rule_08_*`, `rule_10_*`, `rule_11_*` and `rule_14_*`, each written to fail first; budget and kill-switch, path traversal, injection pack and parser fuzzing are trust-gate release gates.
- Personal data (parent; prd Data and compliance): drop files are deleted only after successful processing; parsed text stays in the project's local database.
- Release shape (parent; D10; owner decision 2026-11-18): v0.1 is E1–E4 with the CLI gate and the owner shadow-runs the owner's own departments beside Paperclip from it; the official four-week dogfood clock starts after epic 9 on a frozen build, and v1.0 additionally requires at least the final 2 clean weeks on the v0.9-rc build.

## Done when

- With FakeClock, a Tuesday 08:00 Asia/Kolkata trigger reads back in words and fires once; a jump across the fire time starts exactly one catch-up run on wake, and skip and all behave as named; a manual start records origin manual and queues behind an active run.
- Files of any type dropped in a seat's folder (PDF, xlsx, docx, images and text among them) are processed once by content hash, text as text records and the rest as file records the seat's model reads natively or refuses in words, and deleted, archived or kept after their result commits; an oversize, zip-bomb, page-bomb, timed-out or symlink-escaping file is refused with a reason while the engine keeps running.
- The budget suite shows settled spend never exceeds a cap at any scope; a breach makes no call, raises a Budget ask and pauses the affected schedules; scheduled runs use their lower caps; only a Human resolves the ask or resumes a schedule.
- `agentic stop` cancels every running step at the next safe point and pauses every schedule, and after a restart nothing starts until the owner resumes each schedule.
- On the owner's Mac, after `agentic service install` and a log-out and log-in, the server is running and `agentic open` lands signed in; the stop flag still holds under the login item.
- The injection pack yields zero outbound calls and zero approvable proposals; the external-effect fixture tool runs only after Approve once, with its exact payload; a department zip import shows its diff of tools, MCP servers, schedules and egress hosts and applies nothing until a Human applies it; confirm-token replay and expiry are refused.
- v0.1 is tagged from main after the golden run passes on FakeLlm and one real local model, with `just check` and the RULE-8, RULE-10, RULE-11 and RULE-14 trust suites green, F2's trigger chain reaching F1 in the golden run, and the owner starts shadow-running the owner's own departments beside Paperclip.
- An event trigger starts a workflow in another department on a document update, step completion or workflow completion; `agentic validate` rejects a trigger cycle with file, line and fix, and at run time a start past the maximum chain depth or into a workflow already in the chain is refused with a Failure item and an audit entry.
