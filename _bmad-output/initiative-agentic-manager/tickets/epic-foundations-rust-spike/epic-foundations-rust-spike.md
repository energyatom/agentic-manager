# Foundations and Rust spike

## Description

Opens the build. Story 1 is the two-week spike: the nine criteria are proved inside the real workspace behind the real ports and each gets a verdict in the spike report; two or more failures stop this initiative for a REPLAN around the hybrid (arch AD-2). Then the platform baseline every later epic builds on: the Cargo workspace with enforced dependency direction, CI running `just check`, the licence allow-list, the am-testkit fakes, the single-writer SQLite store with forward-only migrations, Actor and the hash-chained audit log, and am-config's loader, validator, atomic writer, History and Undo, with the Blank department, the role templates and the Company A sample validated in CI.

## Outcome

The owner, and the coding agents building for the owner, get a proven stack and a validated, versioned config foundation, so later epics build on contracts that do not move.

## Requirements

- R1 (parent R1; arch AD-16, AD-35): All configuration loads from plain YAML and Markdown-frontmatter files in the project layout into one immutable snapshot keyed by content hash; config files hold no secrets or runtime state, which lives in the git-ignored `.agentic/` folder; `agentic validate` reports each error with file, line and fix and exits non-zero.
- R2 (parent R2; arch AD-16): A config file changed outside the app raises a changed-on-disk event with its diff, and nothing applies until the owner chooses Reload; the app's own writes never raise it. The banner and Show diff render in epic-org-seats-ui.
- R3 (parent R3; arch AD-16, AD-24): Every config edit through the command path is written atomically and recorded in History with its diff, Actor and hat; Undo applies the inverse as a new History entry and an older entry can be restored. The ⌘Z binding and Undo toast render in epic-org-seats-ui.
- R4 (parent R5; arch AD-7): A newer binary opens an older project without loss: database migrations are forward-only, run after a backup and reported; every config file carries `schema_version` and a config migration is shown as a diff and written only on the owner's accept; a database newer than the binary is refused; only the three newest pre-migration backups are kept, apart from the daily ones, and a config file newer than the binary is refused (restated 2026-11-20, architect REPLAN; arch AD-7).
- R5 (parent R26, R59, R60, R62, R64, R73, R74, R75, R77; arch AD-23, AD-38, AD-40 to AD-44; reference-workload; restated 2026-11-18, owner REPLAN and Amendment 2): The Blank department template, the eight generic role templates (Head, Coordinator, Analyst, Researcher, Reviewer, Writer, Specialist, Human seat; restated 2026-11-18, reconcile) and the optional "Sample company: Company A (two departments)" ship under `templates/` and pass `agentic validate` in CI; every role template carries a goal, a backstory and empty skills, knowledge and links lists; the sample carries the reference company's Owner, departments D1 and D2 and their seats with goal, backstory and avatar tint, its documents, Table T1, read grant, accepts lists, flows F1 and F2, skills, Local Repository Source and team Knowledge, each Source with owner seat, scope, schedule, limits and output; no domain department template ships, and no sample name appears in `crates/` or `web/`.
- R6 (stack-spike; arch AD-1, AD-2, Deferred): Each of the nine stack-spike criteria ends as a runnable test or recorded demo with a pass or fail verdict in the spike report, which also records the pinned toolchain, the OpenAI cloud API choice (file parts through the Responses API, arch AD-31), Ollama's loaded-context field and any unsafe-code exception; two or more failures among criteria 1-7 and 9 open a REPLAN around the hybrid before epic 2 starts, and a single failure records its local workaround; criterion 8 (signed, notarised clean-Mac build) is deferred to a gate at the start of epic 11 story 3 and is not counted (restated 2026-11-19, owner answers); criterion 4 is "Files to models": a mixed folder linked read-only under the confinement rules and its files attached to a frontier and a local vision-capable model, recording which types each accepts (restated 2026-11-19, owner folder-access direction).
- R7 (arch AD-3, AD-4, AD-23, AD-33; amelia Autonomous build; trust-gate Supply chain and CI): CI on every push runs `just check` (fmt, clippy `-D warnings`, nextest, `agentic validate` over `templates/` and `fixtures/`), the dependency-direction check, the licence policy with cargo-deny and cargo-audit and the department-noun denylist scan, with SHA-pinned least-privilege actions on macOS arm64, and builds the `agentic` binary there; a Linux portability job builds every crate but am-desktop and runs the unit tests (restated 2026-11-19, owner Mac first; arch AD-47; no Windows job in v1); the build hook refuses a story whose `just check` is not green.
- R8 (arch AD-33; amelia Autonomous build): `am-testkit` provides FakeLlm (scripted turns, streamed text, usage, tool calls, timeouts and faults), FakeClock, FakeSecretStore and recorded HTTP fixtures, so no test needs the network or a real model.
- R9 (arch AD-6, AD-24, AD-32): Every mutation is a typed writer command with a mandatory Actor, committed with its audit entry in one transaction on the single read-write connection; readers are read-only; one process holds a project through a lock file that names the holder; `.agentic/` is 0700 and its files 0600. (restated 2026-11-20, architect REPLAN; arch AD-32:) `.agentic/` is the project's runtime folder, outside the project at `~/Library/Application Support/agentic-manager-projects/<project-id>/`, found through `project_id` in `company.yaml`; a copied project is refused until its id is removed, a moved one is recorded, a legacy in-project `.agentic/` is moved and verified on first open, and the only runtime file left in a project is the `.agentic-open` marker, which refuses a second Mac until the owner takes the project over.
- R10 (parent constraint Audit; prd RULE-16; arch AD-25): The audit log is append-only and hash-chained, refuses UPDATE and DELETE, holds ids, hashes and redacted arguments but never row content or secrets, exports as JSON Lines, and a tampered chain is detected at the altered entry.
- R11 (parent R58, R59, R60, R61, R62, R64 schema part, owned by epic-org-seats-ui, epic-tools-mcp-search-doctor and epic-connectors-sources; arch AD-35, AD-38, Structural Seed): Seat files carry identity (name, role, goal, backstory, avatar tint), skills, knowledge and links in their frontmatter, and skill folders under `skills/<id>/` follow the Agent Skills format; `agentic validate` checks them with file, line and fix (unknown skill id, SKILL.md without name or description, a script or unsupported file in a skill folder, size caps, a goal or backstory over its cap, a link that is not http or https), warns on a link host outside the seat's allow-list and on a missing reference file, and reads a skill's `allowed-tools` only as information, never as a grant; Source files `sources/<id>.yaml` are validated the same way (known connector type, owner seat exists, Account exists when the type needs one, scope globs compile, hosts are http or https, limits within caps, output table and key exist, mapping fields exist, `render` only on HTTP Reader and Crawler Sources, a crawl-service Account's base URL is https or a loopback port; a host outside the owner seat's allow-list and an empty terms_checked on a website Source are warnings) (restated 2026-11-18). (restated 2026-11-20, architect REPLAN; arch AD-48:) A seat file's `allowed_hosts` host patterns (exact lowercase host, or `*.` and a domain of two or more labels) are validated with file, line and fix and replace `tools.yaml` `egress_hosts` as the seat's allow-list through a config migration accepted by the owner; link-host and Source scope-host warnings check the owner seat's `allowed_hosts`.
- R14 (parent R81, R82 schema part, owned by epic-org-seats-ui and epic-connectors-sources; arch AD-46; added 2026-11-18): A seat file's `capabilities` block (nine capabilities, each on or off with a Built-in or Account provider; missing entries default to Folder access on and the rest off; restated 2026-11-19: Documents & knowledge renamed Folder access, with the seat's `folders` list (path, read or read_write access, patterns) and `text_fallback` switch validated, the app data dir, `.agentic/`, /, ~ and ~/Library refused; restated 2026-11-20, architect REPLAN, arch AD-30: except folders at or below `~/Library/CloudStorage/<provider>/` and below iCloud Drive's `~/Library/Mobile Documents/com~apple~CloudDocs/`, and refusing any folder that is, contains or lies inside a project root) validates and expands at load by one fixed table into the seat's built-in tool grants; a built-in tool listed while its capability is off, or a provider Account of the wrong kind, fails `agentic validate` with file, line and fix; every role template and the Company A sample carry their capabilities, the sample all on Built-in providers.

## Constraints

- Stack (parent Stack; C2, D4; arch AD-1, AD-5): Rust core in one binary with the UI embedded later; pre-1.0 crates only behind the project's own ports, no foreign types in am-domain or port signatures; exact versions pinned with a `docs/crate-notes` page each.
- Licence (parent Licence; C1; arch AD-3): MIT everywhere; only MIT, Apache-2.0, BSD-2/3-Clause, ISC, Zlib, Unicode-3.0 and MPL-2.0 dependencies; GPL, LGPL and AGPL fail CI; bundled native binaries recorded in THIRD_PARTY.md.
- Files are truth (parent Files are truth; prd RULE-4; C6): configuration files are the source of truth; no silent two-way sync.
- Developer quality (parent Developer quality; bNFR-8, bNFR-11): a deterministic fake provider; structured logs; at least 80% coverage on am-engine and am-store, gated in CI from epic-workflow-engine-cli when am-engine exists.
- Generic engine (parent Generic engine; prd RULE-2; D7): department vocabulary only under `templates/` and `fixtures/`; the denylist scan starts in this epic.
- Failing-first tests and Build discipline (parent; D11): acceptance tests are written from the ticket before code; the RULE-16 test lands here as `crates/am-e2e/tests/trust/rule_16_*.rs`, written to fail first; no story spans milestones.

## Done when

- The spike report records a pass or fail verdict for each of the nine stack-spike criteria, each backed by a runnable test or recorded demo; with two or more failures the REPLAN is opened before epic 2 starts.
- `agentic validate` passes on the Blank department, the Company A sample and every role template (each seat with goal, backstory, skills, knowledge and links), and a deliberately broken file, including a skill folder holding a script, is reported with file, line and fix.
- A config edit through the command path writes the file atomically and appears in History with diff, actor and hat; one Undo restores it; an outside edit raises a changed-on-disk event and nothing applies until Reload.
- An older project fixture opens on the new binary: the database migrates after a backup with the migration reported, the config migration applies only on accept, and a database newer than the binary is refused.
- Merged to main with `just check`, the licence policy, the dependency-direction check, the department-noun denylist scan and the audit-chain test green in CI, every test running on the am-testkit fakes without network, and the `agentic` binary built in CI.

## Boundaries

- In: workspace and CI baseline, store writer and readers, migrations, audit log, Actor, config loader, validator, writer, watcher, History and Undo, the `templates/` folder, am-testkit.
- Out: Accounts and providers (epic-accounts-model-routing); run execution (epic-workflow-engine-cli); any UI. The reload banner and the ⌘Z binding render in epic-org-seats-ui, consuming this epic's changed-on-disk event and Undo command.
- Out: built-in tool and connector implementations (epic-connectors-sources; MCP in epic-tools-mcp-search-doctor); the validator knows tool ids and connector types from their manifests only.
- Out: release jobs, signing in CI and the trust-gate supply-chain items beyond the licence policy (epic-desktop-release-trust-gate); the spike's signed build is a one-off proof.
- Touch point: GitHub Actions — the CI baseline starts here; release jobs belong to epic-desktop-release-trust-gate.
