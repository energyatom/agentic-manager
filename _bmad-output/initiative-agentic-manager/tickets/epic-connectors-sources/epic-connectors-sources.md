# Connectors and Sources

## Description

Generic connectors as technical building blocks, as the owner directed on 2026-11-18: Web Search (the built-in Local search, a bundled and supervised SearXNG, with keyed providers and public instances as optional upgrades; restated 2026-11-18, Open by default), HTTP Reader and the reader tools, a built-in crawler for static pages that can also render pages built by scripts in a browser already installed on the owner's computer (restated 2026-11-18), one Firecrawl-compatible crawl endpoint, self-hosted by default, API and Feed Sources with field mapping and no code, Local Repository loads into tables with an ingest report and cleanup after a successful load, and searchable Knowledge per seat or team; and, as the owner directed on 2026-11-19, Folder access: a seat links folders (read-only by default) whose files its model reads natively, or as plain text through an optional fallback, or refuses in words, and a workflow fans out over a folder by file pattern so several models read different files and a gathering seat consolidates them. Every Source is a configured instance owned by a seat (Account, scope, schedule, limits, output, incremental state), loaded without a model, capped, with paid use counted as spend, respecting robots.txt, healthy in the Connectors surface, and read as untrusted content. Named sources exist only as Source files in templates and fixtures (the Company A sample's Local Repository Source and the fixture Sources over the loopback fixture site); cleaning, normalising and enriching loaded data are the configured seats' jobs, never connector features (owner REPLAN, 2026-11-18). Split out of epic-tools-mcp-search-doctor on 2026-11-18; it builds before it, so the frozen dogfood build includes every connector.

## Outcome

The owner's departments pull web pages, feeds, APIs and the owner's own files in on a schedule through a few generic connectors the owner configures without code, each load showing what was new, what changed and what it cost, and nothing processed twice.

## Requirements

- R1 (parent R64; arch AD-39, AD-23, AD-35, AD-15): Connector types are listed in one catalogue (Web Search, HTTP Reader, Crawler, API, Feed, Local Repository, Knowledge, Database, MCP, Actions) with their availability; a Source file `sources/<id>.yaml` names its type, owner seat, optional Account, scope, optional trigger, limits, output (a table with mapping and key, records, or knowledge) and, for websites, the date the owner checked the site's terms; a load is a load run without a model whose requests come only from the Source file and in-scope responses; every record carries provenance (Source, connector, URL or file, fetched-at, content hash, load run) and is UntrustedData, rows written by a load carrying taint; no connector, UI string or code path in `crates/` or `web/` names a department source; a Source that adds hosts to its owner seat's allow-list, a new Account or a raised limit is privilege-widening.
- R2 (parent R46; arch AD-11, AD-12, AD-10, AD-39; was epic 9 R1, moved 2026-11-18): Built-in web search, read website, arXiv, read file, read URL and search knowledge each declare an action class, network needs and a per-step use count in their manifest, reach a seat only when its seat file grants them, reach the web only through the Web Search and HTTP Reader connectors and `Fetcher` (egress client, robots.txt, per-host pace) to the seat's allow-list, and return UntrustedData that taints the step; in a tainted step read website and read URL fetch only a URL recorded for the step (its trusted inputs, saved links, claimed link lists, source records it read, or search results) used as-is, and web search uses only words from the step's Instruction parts, anything else becoming an Approval with the exact URL or query (parent constraint Untrusted content; arch AD-11); read URL's pages are extracted in the capped extract child, and read file belongs to Folder access (R22; restated 2026-11-19).
- R3 (parent R46, R79; D8; was epic 9 R2; restated 2026-11-18, Open by default): Web search works with no signup and no key through Local search (SearXNG), labelled "Local search (SearXNG)" wherever search is named, with each result labelled by the engine that returned it.
- R4 (parent R46; D8; prd OQ-4; was epic 9 R3; restated 2026-11-18): A comparison of Local search (SearXNG) with Brave, Tavily, Exa and Serper on at least 20 real queries the owner supplies from the owner's own departments' research steps records relevance, coverage of the regions the owner works in, sign-up friction, free tier, terms and attribution, latency, cost and Local search's rate-limit failures, recommends which keyed provider, if any, is named as the optional upgrade, the default engine list and delay, and whether scheduled runs may fall back to an opt-in public SearXNG instance; the owner's choice is recorded; Local search stays the default.
- R5 (parent R46, R70; arch AD-5, AD-17, AD-12, AD-9; ux Voice and Tone; D8; was epic 9 R4): Brave, Tavily, Exa and Serper, and public or self-hosted SearXNG instances, sit behind SearchProvider in the Web Search connector as optional Accounts, never pre-selected; a provider key is stored only in the keychain; adding a provider adds its egress host through the privilege-widening confirmation ("D1-E1 may send search queries to api.tavily.com."); keyed queries are service spend priced per call; a service with a no-key allowance or a free key is an optional Account the same way; Settings › Search shows Local search as the default with its engines, delay, disclosure and status (restated 2026-11-18, Open by default).
- R6 (parent R65; parent constraints Robots and terms, Connector caps, Incremental state; arch AD-39, AD-12): The built-in crawler reads static HTML only within its Source's scope (start pages, allowed hosts, include and exclude path globs, depth, page budget), drops query strings unless a glob names them, records out-of-scope links as skipped, keeps its frontier in SQLite so a killed load resumes without refetching committed pages, sends conditional requests and loads only new or changed pages, honours robots.txt (unreachable or 5xx disallows) and Crawl-delay with at least 1 s between requests to one host, and never fetches more pages than its budget; with `render: true` it loads pages through the Rendered Reader (R17) under the same rules (restated 2026-11-18).
- R7 (parent R65, R70; arch AD-39, AD-17, AD-9, AD-12; restated 2026-11-18, owner decision on free crawling): The crawl-service adapter behind `CrawlService` runs a Crawler Source through a Firecrawl-compatible API endpoint named by a crawl-service Account (its base URL: by default a service the owner self-hosts on loopback, such as `http://localhost:3002` with no key, or Firecrawl cloud with a key in the keychain; adding either is privilege-widening): it submits only the Source's scope (start URL, include and exclude paths, depth, page budget, no external links or subdomains, query strings ignored, Markdown of main content), never asks to ignore robots.txt, drops any returned page whose URL robots.txt disallows, reserves page budget × credits per page × price before submitting (price 0 for a self-hosted endpoint), polls to a final status and reads every result page at once, stores each page as an untrusted record, and settles from the credits the service reports.
- R8 (parent R66; arch AD-39, AD-17): An API Source reads a REST/JSON endpoint with its Account's credentials (header or query key from the keychain), follows cursor, page-number or link-header pagination to its item budget, and maps response fields to table fields by declarative paths with a key, rejecting a row that fails a type with its reason; a Feed Source reads RSS, Atom and JSON Feed and loads only new or changed entries; a sitemap seeds a Crawler Source's frontier within its scope.
- R9 (parent R67, R19; parent constraint Incremental state; arch AD-30, AD-39): A Local Repository Source with a table output maps xlsx, csv and json rows to the table by declarative columns, upserts by its key (within a file the last duplicate wins and is counted), rejects rows with reasons, and writes an ingest report (rows read, new, updated, unchanged, duplicates by hash and by key, rejected, files cleaned up); the file is deleted (default), archived or kept only after the load transaction committed, and a failed load leaves it in place with a Failure item.
- R10 (parent R68, R62; parent constraints Seat anatomy safety, Files; arch AD-39, AD-30, AD-10; was epic 9 R15 reference-file part): A seat's or team's Knowledge in `.agentic/knowledge/` is indexed for keyword search over its text-readable files (text files and PDF text layers; other files are found by name; restated 2026-11-19); `search_knowledge` (read class, local, no network) returns ranked snippets labelled with file and page as UntrustedData that taints the step; `read_file` (Folder access, R22) for a seat resolves only in its knowledge folder, its team's, its claimed file records and its linked folders; the app never deletes, moves or claims a knowledge file; a team's Knowledge is readable only by that team's seats.
- R11 (parent R62; parent constraints Untrusted content, Seat anatomy safety; arch AD-30, AD-11, AD-12; was epic 9 R15 link-list part): A link list in a Local Repository folder (`links.txt`, `.url`, `.webloc`, at most 50 http or https URLs) is claimed once by hash, each URL fetched once through the HTTP Reader within the owner seat's allow-list and robots.txt and stored as an untrusted record whose URL counts as recorded for the steps that read it, while a URL on an unlisted, private, link-local or metadata host is not fetched and is reported for the Agent card's skipped-hosts line.
- R12 (parent R61, R62; arch AD-11, AD-12, AD-18, AD-39; was epic 9 R14 and the saved-link part of R15): Read website, read URL, read file, arXiv and search knowledge act as the seat's readers over its saved links, search results and source records; saved links are URLs recorded for each of the seat's steps, fetched only as written on allow-listed hosts; watching pages is a Crawler or HTTP Reader Source that loads only changed pages, or a scheduled step re-reading saved links; no model-invoked tool follows a link found in a page; the API gives the Agent card each seat's Sources with type, output, schedule and health, and the how-to for watching pages ships in `docs/`.
- R13 (parent R69, R64; ux EXPERIENCE Connectors surface, Connector catalogue, Source detail, Add Source, Test connector, Ingest report; arch AD-39): The Connectors surface (⌘9) lists Sources with health, last and next load and this week's spend, shows the catalogue by group, and adds a Source in six steps whose Test connector checks credentials, reachability, robots.txt, allow-list and size and shows a one-item sample with its mapping and stated cost while writing nothing; a website Source cannot be saved without the site-terms check; each Source shows its last error, its ingest reports and its load runs; a website Source's Scope step carries the rendering toggle, showing the browser found or "Browser not found" (restated 2026-11-18); the health of every Source and connector Account, and whether a browser for rendering is installed, is available to Doctor.
- R14 (parent R70; parent constraint Connector caps; arch AD-9, AD-11, AD-39): Source limits (items, bytes and spend per load, loads per day, pace per host) are checked before each request and a tool's per-step use count before each call; paid connector use is service spend priced from the dated services section of the price file, reserved before the call against the Source or step, seat, workflow and company scopes, settled from reported usage, shown on the meter and in Models & Costs, and a reservation that would cross a cap makes no call and raises a Budget ask.
- R15 (parent R71; parent constraint Incremental state; arch AD-8, AD-39): Every Source keeps item keys, content hashes, ETags, frontier and cursors; a load over unchanged input writes nothing; each consuming step reads only records new or changed since its last successful run through a cursor that advances in the step's commit; an interrupted load resumes without repeating committed work.
- R17 (parent R72; parent constraints Rendered pages, Robots and terms, Connector caps, Untrusted content; arch AD-39, AD-12, AD-13): An HTTP Reader or Crawler Source with `render: true` loads each page in a Chrome, Chromium or Edge found on the computer or at a path the owner sets, never bundled or downloaded, through `PageRenderer` in a separate `agentic __render` child that launches it with a fresh temporary profile deleted after the load and its sandbox on; every request the page makes is performed by the parent through `Fetcher` within the Source's scope hosts and the owner seat's allow-list, with robots.txt, at least 1 s per host and the byte budget, and images, media, fonts and beacons are not fetched; each page has a render timeout (default 60 s, at most 120 s) and a request cap (default 50), and the load's page budget and caps hold; the rendered page goes through the same extract, dedupe and ingest report as a static page and is UntrustedData; nothing masks automation; with no browser found the Source is not loaded, shows "Browser not found", and the health API gives Doctor the fix, while rendering-off Sources keep loading.
- R16 (parent constraints Untrusted content, Generic engine, AI ship and rollback; parent R26): The injection pack gains connector cases (a poisoned crawled page, feed item, API field, spreadsheet cell, link-list page, knowledge file and saved-link page) that yield zero outbound calls, zero approvable proposals and zero requests carrying a canary on the fake provider and one real local model; the Company A sample's Source and the fixture Sources over the loopback fixture site ship as Source files under `templates/` and `fixtures/` and load green end to end, with the denylist scan clean (restated 2026-11-18, owner REPLAN).

- R18 (parent R78, R79; parent constraints Open by default, Local search service; arch AD-45; added 2026-11-18): Local search ships in the install as a pinned SearXNG tree (its own Python and Granian) verified by hash, configured for JSON only with a default engine list, started, health-checked, restarted and logged by the app, listening only on an owner-only Unix socket with no TCP listener (restated 2026-11-19, owner Mac first: the Windows loopback variant is v1.x), with its secret key in the keychain, a scrubbed environment and no access to app or project data; its engine traffic goes through the app's egress proxy to the enabled engines' hosts at the set delay; it updates only with consent and removes cleanly; its status reaches Doctor and Settings › Search.
- R19 (retired 2026-11-19, owner folder-access direction): local OCR by the bundled Tesseract; OCR is a vision- or OCR-capable model the owner assigns to the seat (R22); id kept, never reused.
- R21 (retired 2026-11-19, owner folder-access direction): a Local OCR service (for example PaddleOCR) as Documents & knowledge's OCR provider; a local OCR or vision model served by LM Studio or Ollama is chosen as the seat's model instead; id kept, never reused.
- R20 (parent R81, R82, R78; arch AD-46; added 2026-11-18): A seat's capabilities expand into its built-in tool grants by one fixed table; a capability that is off leaves its tools absent and refused; switching one on or choosing an Account provider is privilege-widening; each built-in capability but Folder access (whose reader is the seat's model; restated 2026-11-19) can route to an Account of a matching kind, with its spend metered and no silent fallback to another paid provider; with every capability on Built-in and no keys, the zero-key golden Company A F1 run, its web search step included, passes.
- R22 (parent R83, R80, R81; parent constraints Files, Untrusted content, Personal data; arch AD-30, AD-31, AD-5, AD-10, AD-11, AD-15, AD-27, AD-46; added 2026-11-19, owner: "What I want is folder reading access — a tool that I can link to the model"): A seat's Folder access capability links the folders in its seat file's `folders:` list, each read-only unless its write switch is on, as grant roots (canonicalised, symlink escapes refused, the app data dir, any `.agentic/` folder, the filesystem root, the home folder and ~/Library refused); `list_files` lists and filters by glob, type, size and date; `read_file` attaches a file to the seat's model natively when its file chip covers the type, as `text-fallback` text when the seat's text fallback is on and the file is text-readable, and otherwise returns a worded refusal naming the type and the remedy with zero bytes sent; `write_file` exists only with the write switch on and never deletes, moves or renames; every file read is UntrustedData that taints the step; per-step caps on files and bytes are enforced; file parts reserve and settle model spend; linking a folder (or switching on write) is privilege-widening, and linking one to a seat whose model or fallback is a cloud Account, or moving such a seat to one, says the files leave this Mac and needs the two-step confirmation; every list, read and write is audited.
- R23 (parent R84; arch AD-40, AD-30; mockup `mockups/key-workflow-run.html`; added 2026-11-19): A fan-out step declares `over_folder` with 2 to 8 pattern routes to seats and `files: new_or_changed | all`; each route becomes a branch reading only its matching files under its seat's model, caps and taint; unmatched files reach the fan-in as an `unrouted` list; the gathering seat's fan-in receives every branch output labelled by seat with the files it covered; `agentic validate` checks each route's seat links the folder and warns, disabling Run now with the reason, when a route's type is one its seat's model cannot read; the workflow editor and run view show the routes, per-branch files and the unrouted list as drawn in the mockup.

- Local search service (parent; arch AD-45; added 2026-11-18): owned here; the supervised-restart, loopback-only and secret, scrubbed-env, consent-gated update and egress tests land as `crates/am-e2e/tests/trust/local_search_*.rs`, written to fail first (story 18).
- Robots and terms (parent; arch AD-39, AD-12): owned here; the robots and terms tests land as `crates/am-e2e/tests/trust/connectors_robots_*.rs`, written to fail first.
- Rendered pages (parent; arch AD-39, AD-12, AD-13): owned here; the fresh-profile, egress, robots, budget, timeout and no-browser tests land as `crates/am-e2e/tests/trust/connectors_render_*.rs`, written to fail first.
- Connector caps (parent; arch AD-9, AD-11, AD-39): owned here; page budget, use count and service-spend tests are written to fail first.
- Incremental state (parent; arch AD-30, AD-39): owned here; idempotent loads and cleanup-after-commit tests are written to fail first.
- Untrusted content (parent; prd RULE-8; arch AD-10, AD-11): every source record, connector result and knowledge snippet is UntrustedData; loads run no model.
- Egress (parent; prd RULE-9; arch AD-12): every connector and reader request goes through `Fetcher` and the egress client; Source hosts stay within the owner seat's allow-list.
- Secrets (parent; prd RULE-12; arch AD-17): search, API and crawl-service keys live only in the keychain; leak scans stay clean.
- Files (parent; prd RULE-14; arch AD-30; restated 2026-11-19): Local Repository files and linked folders are confined and capped; text and table rows are read in the extract child; drop files are deleted only after the load committed; nothing is ever deleted, moved or renamed in a linked folder; the folder trust tests land as `crates/am-e2e/tests/trust/folder_access_*.rs`, written to fail first (stories 22 and 23).
- Generic engine (parent; prd RULE-2; arch AD-23): connector code and UI name only types; department sources are template Source files.
- Propose, then approve (parent; prd RULE-3): new Source hosts, Accounts, search providers and raised limits use the two-step confirmation.
- Mockups gate UI (parent): the Connectors surface, catalogue (Web Search card: "Local search (SearXNG) — free, no key" as default, keyed providers optional), Add Source and ingest report match `key-connectors.html`; the Agent card's Sources group matches its §4; the Folder access chip with its linked folders and file-type badges matches `key-seat-sheet.html` and the folder fan-out matches `key-workflow-run.html` (added 2026-11-19); Settings › Search is spine-only.

## Done when

- A built-in Crawler Source over the fixture site's synthetic pages, owned by D1-E1, loads within its scope and page budget at a polite pace, skips what robots.txt disallows, loads only new or changed pages on the second run, and D1-E1's step reads only those records, fenced as untrusted.
- A rendered Crawler Source loads a page built by scripts in the installed browser with a fresh profile, every request inside its scope, robots.txt and page budget, and a machine with no browser shows "Browser not found" and Doctor's fix while other Sources keep loading.
- A Source on a Firecrawl-compatible endpoint (self-hosted on loopback, or cloud) reserves its credits before submitting (₹0 when self-hosted), settles from the reported credits on the meter, never asks the service to ignore robots.txt, drops pages robots.txt disallows, and stops with a Budget ask when a cap would be crossed.
- An API Source, a Feed Source and the Company A Local Repository load into Table T1 map declared fields without code and upsert by key, each showing an ingest report; the spreadsheet file is deleted only after its rows were saved, and dropping it again writes nothing.
- D1-E1's search, readers, saved links, link lists and searchable Knowledge work as in epic 9's former stories, web search through Local search with no key; keyed search, when the owner adds it, is priced as spend and never pre-selected.
- On a fresh install with only a local model server and no keys, the golden Company A F1 run completes with a web search step answered by Local search (RULE-20); a killed SearXNG restarts on its own and Doctor shows its status; a capability switched off leaves its tools refused, and a seat switched to a keyed provider sends its queries there and pays for them on the meter.
- D1-E1, D1-E2 and D1-E3 link the Company A folder read-only, and flow F3 fans out over it by pattern (PDFs to D1-E1, csv to D1-E2 through the text fallback, images to D1-E3): each file reaches its seat's model natively or as fallback text, fenced as untrusted, a type a seat's model cannot read is refused in words with zero bytes sent, unrouted files reach D1-Head's gathering step listed, linking the folder to a cloud-model seat took the two-step confirmation, and a write to the read-only folder is refused (added 2026-11-19).
- The Connectors surface and Add Source with Test connector match the mockup; Doctor can read every Source's health; the Company A sample's and the fixtures' Sources validate and load green end to end with the connector injection cases passing.

## Boundaries

- Out: Apify, Spider, Browserbase and Crawl4AI adapters, crawling of login-gated pages, external databases, cloud storage and semantic knowledge search (v1.x, arch Deferred); bundling or downloading a browser, using the owner's own browser profile, and any stealth or anti-bot evasion (never); webhooks (v1.x) and approve-then-send (v1.1 Team release, owner 2026-11-18); a model-invoked crawler or API tool (none in v1); built-in per-format readers (Word, PowerPoint, Excel to text) and bundled OCR (owner, 2026-11-19: formats are what the seat's model reads); one fan-out branch per file (v1.x).
- Out: MCP servers, Doctor's checks and fixes, backups, the About page and the dogfood freeze (epic-tools-mcp-search-doctor, which waits on this epic); ToolGate classes, taint, the extract child and the Local Repository core with cleanup after commit (epic-triggers-budgets-safety-floor, story 7); the Agent card shell, Tools library and privilege-widening dialog (epic-org-seats-ui); the Source schema in `agentic validate` and the Company A sample's Source files (epic-foundations-rust-spike, stories 12 and 5).
- Touch point: SearXNG (AGPL-3.0, bundled unmodified, pinned commit, separate process) and the public search engines it queries through the egress proxy; installers carrying it are epic-desktop-release-trust-gate's (11.16).
- Touch point: optional search providers (Brave, Tavily, Exa, Serper, public SearXNG instances) and a Firecrawl-compatible crawl endpoint (self-hosted by the owner by default, Firecrawl cloud optional) — called through the egress client with the owner's keys where needed; external; the app links and ships none of the service's code.
- Touch point: folders on the owner's Mac linked to seats — read within their grant root, written only with the write switch, never deleted or moved; and the providers' native file inputs (arch AD-31), built in epic-accounts-model-routing (2.9).
- Touch point: a Chrome, Chromium or Edge the owner installed — launched headless by `agentic __render` with a fresh profile; external, never bundled or changed.
- Touch point: websites read by Sources and readers — fetched within scope, allow-list and robots.txt; external, never changed.
- Must not change: the tainted-read rule (AD-11) for model-invoked tools; reference files are never deleted or moved.
