# Org and Seats UI with live cost meter and first-run wizard

## Description

The browser-mode app shell (sidebar, ⌘K, a toolbar with company name, meter and Stop everything, the reload banner and ⌘Z Undo; DESIGN tokens in light and dark); the first-run wizard (company, Accounts, template, short test); the org chart with its team-box and seat-card toggle; seat and team editing by drag, panel or keyboard in the seat sheet with the Account › Model picker and chips from epic 2; Models & Costs with Accounts and costs; human seats with hats, CEO goals and Vision Creator notes; the "what this seat can touch" panel; the live meter and pre-run estimate with the Workflows list that carries Run now; the import dialog; and the privilege-widening confirmation dialog, carrying epic 4's confirm token, that epics 6, 7, 8 and 9 reuse.

## Outcome

The owner sets up and steers his AI company from an org chart in under 10 minutes, with spend and safety visible at a glance.

## Requirements

- R1 (parent R22; ux First-run wizard, State Patterns Wizard; sally Apple-like): With no company file in the served folder the app opens a wizard of four screens (company with timezone and currency pre-filled from the Mac's system locale; Accounts with local servers detected and a cloud key checked before it is stored; Blank or "Sample company: Company A (two departments)" applied as the import Proposal by the owner's Continue; a short test where each seat answers one short prompt with time and cost, its estimate range shown before it starts, unavailable models falling back in words, a slow local model load shown with elapsed time and never failed on time alone (Keep waiting, Skip this seat, Skip test), and a model that fails the tool-call probe named without blocking) that ends on a populated org chart; step 2 also covers no local server (with one sentence and links on getting LM Studio or Ollama), a local server with no model loaded, and adding an OpenAI-compatible URL with its host shown; quitting resumes at the same step, nothing blocks finishing, and the wizard targets under 10 minutes (ux EXPERIENCE Time targets; amended 2026-11-18, final review UX high 2, M1, M2).
- R2 (parent R23; ux Org chart, Team box, Seat card; arch Deferred org-chart rendering): The org chart is a top-down ARIA tree that toggles per team (Space) and globally (Teams/Seats, ⇧⌘E) between team boxes (name, status sentence, weekly cost, avatar strip with seat count and how many are you, newest guidance note) and seat cards (avatar, name, role, occupant and model, status, this week's spend); arrows move selection, Return opens the sheet, Fit and zoom work by key, more than 5 reports wrap in rows of 5, expand state persists per team, and 30 seats render at 60 fps and fit 1440×900 at 80%.
- R3 (parent R24; ux Role template menu, Flow 5): Seats and teams are added, moved and removed by drag, context menu and keyboard (N role template menu, ⌥↑/⌥↓, Move to…), each as one undoable config edit; a seat from a role template is created in under 60 seconds by mouse and by keyboard alone; removing a seat used in a workflow asks first and a team is removed only when empty.
- R4 (parent R24, R2, R3; arch AD-16; ux Seat sheet, Undo toast, Config changed on disk): The seat sheet edits Instructions (with 'Also receives'), Drop folder, Memory notes and More; fields save on blur or Return as config edits with an Undo toast for 6 s and ⌘Z / ⇧⌘Z; a file changed outside the app shows Reload and Show diff, keeping unsaved edits as a conflict, and an invalid file shows its file:line fix.

## Constraints

- Accessibility (parent; prd RULE-19; ux Accessibility Floor; final review UX M3, 2026-11-18): Definition of Done for every UI story, whether or not its verify repeats it: axe clean in light and dark, its path completed keyboard-only, reduced motion honoured; story 1 adds a token-contrast unit test over DESIGN.md's colour pairs.
- Spend visible (parent, owned; prd RULE-7; D2): spend and status stay visible on the org chart and toolbar; an estimate never raises a cap and is always a range with its basis.
- Propose, then approve (parent; prd RULE-3; arch AD-15): every apply, resume and widening is a Human command from a real UI event; no auto-approve and no always-allow.
- Generic engine (parent; prd RULE-2; arch AD-23): web/src holds no department vocabulary; the denylist scan covers it; nouns come from template data.
- AI never-do (parent): never a single-number estimate and never a chip shown tested without a passed probe.
- Performance (parent; prd RULE-18; arch Deferred performance budgets): interactions under 100 ms and 60 fps at 30 seats are measured from this epic; the budget is owned by epic-polish-dry-run-learning.
- Failing-first tests and Build discipline (parent; D11): each story's Playwright and vitest acceptance tests are written from the ticket before the UI; each UI story names the mockup it matches.
