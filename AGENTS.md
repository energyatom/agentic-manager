## Agentic Manager

Local-first, MIT-licensed app for running departments of AI seats from an org chart; departments hand work to each other, fan it out and review each other. Rust workspace of small `am-*` crates built into one `agentic` binary (engine, loopback HTTP/WebSocket server, scheduler, SQLite) with an embedded React + TypeScript UI; a Tauri 2 shell wraps it later. Planning lives in `_bmad-output/initiative-agentic-manager/`: the initiative, `reference-workload.md` (the abstract Company A every test and sample uses), `architecture-agentic-manager/` (AD-1..AD-47, the binding rules), `ux-agentic-manager/` (DESIGN.md, EXPERIENCE.md, mockups/) and `tickets/` (`tickets.toml`, one folder per epic).

## Policy

- The ticket is the spec: build one story at a time through `bmad-build` / `bmad-build-auto`, write its acceptance tests from the ticket first and see them fail, then implement.
- Never edit the PRD, reference-company spec, initiative, architecture, UX spines or decision record to fit the code; a needed change goes to Sofia (`bmad-agent-po`, REPLAN) and the work waits.
- One story, one commit; never span milestones; keep a story inside one crate boundary where possible.
- Secrets live only in the OS keychain via `am-secrets` (`SecretString`, no Debug/Display/Serialize). Never put a key in config, fixtures, tests, prompts, logs or exports — use FakeSecretStore and canary values.
- Untrusted content (web, search, documents, MCP results, free-text in table rows, seat reference files, pages from saved or dropped links, Source records including rendered pages, knowledge search results, files read from a linked folder and every file part attached to a model call, tainted rows) is `UntrustedData` and never becomes `Instruction`; there is no conversion, and none may be added.
- All network goes through `am-net::EgressClient` and its allow-lists, and every website fetch through `Fetcher` (robots.txt, product user agent, at least 1 s per host); never construct a reqwest client elsewhere, never add a telemetry host or a setting that skips robots.txt.
- Rendered Reader (AD-39): only in `am-render` and its `agentic __render` child, which starts the installed browser with a fresh temporary profile and `--remote-debugging-pipe` (never a debugging port), drives CDP over `am-render`'s own pipe transport on `chromiumoxide_cdp` types, and blocks loopback (`--proxy-bypass-list=<-loopback>`, closed proxy, `--host-resolver-rules`); every page request goes back to the parent's `Fetcher` through CDP `Fetch` interception. Never call `Browser::launch`, `Browser::connect`, `no_sandbox` or `hidden`, never enable chromiumoxide's `fetcher` feature or bundle or download a browser, never use the owner's browser profile, and never add stealth, user-agent spoofing or anti-bot evasion.
- Taint never launders (AD-10): anything a tainted step writes (loop-back or review notes, `ask_seat` questions, rows, documents, workspace files) stays `UntrustedData`, marked at rest, and taints whoever reads it; in a tainted step local-write tools write only declared outputs; a Proposal from a tainted step is never approvable.
- Privilege-widening is decided only by `am-config::is_widening` (AD-15), an exhaustive match over every config field, enforced in the writer on every path (UI, Proposal, import, Assistant, API, Reload, startup); a new config field must be classified there; a Reload or startup that widens holds every run until the two-step confirmation (AD-16); a human review gate is never replaced by an AI reviewer without it.
- Hostile-input children (AD-13): the parser (`agentic-extract __extract`) and Local search's Python run as App Sandbox helpers on macOS and fail closed when the sandbox self-test fails; never add an entitlement to a helper beyond its AD-13 set, never give the main app `disable-library-validation`, and never pass a child a path to the app data dir or a project root (MCP cwd is `.agentic/workspace/mcp/<server-id>/`).
- External-effect tool calls need a Human approval showing the exact payload; v1 has no send tools. Only command handlers carrying `Actor::Human` apply proposals, resolve Inbox items, resume schedules or raise caps — no auto-approve or "always allow".
- No department vocabulary (seat, department, document, table or template names — including the Company A sample's ids such as `d1-head`, `table-t1`, `company-a` — or named source sites and hosts) in `crates/` or `web/src`; nouns and Source files live only in `templates/` and `fixtures/`. A CI denylist scan fails the build. Data cleaning, normalising and enriching are the configured seats' jobs (instructions, skills, tools): never add them as engine or connector features (owner, 2026-11-18).
- Cross-department work follows AD-40..AD-44: a hand-off is refused unless the receiving department `accepts` it; its payload is immutable and keeps its taint and provenance (taint never clears on crossing a department, a review or a trigger); fan-out branches each reserve against the shared run, seat, workflow and company scopes in one writer check and have their own cancellation token; an AI review gate never resolves an Approval, Budget ask or Proposal; lineage is computed from the journal (`step_inputs`), never stored twice; event-trigger chains are refused past `max_chain_depth` or on a cycle.
- Never read or cite `_archive/`: it holds superseded planning inputs.
- Open by default (RULE-20): every capability must work with the built-in, free, key-free provider; never make a key or Account required, and never pre-select a paid provider. The zero-key golden run (a local model server, an empty keychain, F1 with a web search step) must stay green.
- Folder access (AD-30, AD-31, AD-46): a linked folder is a grant root, read-only unless its write switch is on; a file reaches a model only as a native file part its file chips allow, as `text-fallback` text when the seat's switch is on, or as a worded refusal with zero bytes sent. Never add a per-format reader (docx, pptx, xlsx-to-text), an OCR engine or any silent conversion, never add a delete, move or rename tool for linked folders, and never send a file to a cloud model without the two-step folder-link confirmation.
- Capabilities (AD-46) are the only way a seat gets built-in tools: they expand in `am-config` by one fixed table into tool grants; never add a second permission path, and switching one on or choosing an Account provider goes through the privilege-widening confirmation. Calculate & analyse runs no arbitrary code.
- Local search (AD-45) is the bundled SearXNG, supervised only by `am-services`: keep its tree hash-verified, its env scrubbed, its listener an owner-only Unix socket (no TCP listener), its secret key only in the keychain, its engine traffic through `am-net`'s local-service proxy, and its tree changed only inside an app release (no separate updater); the app speaks only HTTP JSON to it.
- v1 targets macOS on Apple Silicon only (AD-47): put OS-specific code only in adapters behind ports (`am-secrets`, `am-services`, `am-app`'s `agentic service` and permission checks, `am-desktop`) under `#[cfg(target_os = "macos")]` with a compiling non-macOS branch that returns a "not supported on this platform yet" error; never call a macOS-only API from the other crates, because the Linux CI job builds them and runs their unit tests; do not add Windows or Linux packaging, signing, release jobs or Windows CI (v1.x).
- Role templates are Head, Coordinator, Analyst, Researcher, Reviewer, Writer, Specialist and Human seat; the learning loop ships with Coordinator; the ad-hoc feature is "Ask a seat". Never name a "Chief of Staff" or "Manager" template.
- Connectors are generic types in `am-connectors` (AD-39): a Source load never calls a model or reads tables, builds requests only from its Source file and in-scope responses, checks its limits before each request, reserves paid service use in the ledger before the call, and deletes a Local Repository file only after the load transaction committed.
- A skill adds instructions only (AD-38): never let ToolGate, the egress client or the touch panel read a skill, and never run a file from a skill folder.
- Licence is MIT for the repo and every crate and package. Dependencies may be only MIT, MIT-0, Apache-2.0, BSD-2/3-Clause, ISC, Zlib, Unicode-3.0 or MPL-2.0 (cargo-deny / npm licence check); never GPL/LGPL/AGPL in the linked graph. A bundled native binary is recorded in `THIRD_PARTY.md`. The bundled SearXNG (AGPL-3.0) ships unmodified as a separate process under `services/searxng/` with its licence and source attached to each release, and a crawl service (Firecrawl, AGPL-3.0) is reached only over HTTP; never link, vendor into a crate, patch or copy either one's code.

## Conventions that differ from defaults

- Rust for agents: no lifetimes in public APIs, `Arc<dyn Port>` for ports, owned `String`/`Vec`, no project macros, `#![forbid(unsafe_code)]` in every crate.
- Before using a pre-1.0 crate (rmcp, PDF crates, croner, calamine, texting_robots, scraper, htmd, dom_smoothie, chromiumoxide, …) read `docs/crate-notes/<crate>.md` for the pinned version; never let its types into `am-domain` or a port signature.
- Every mutation is a typed writer command with an explicit `Actor` (no default), committed with its audit entry; reads use read-only connections. Never write SQLite directly from another crate.
- Only `am-config` reads or writes project config files; only ToolGate calls tools; file access takes a `WorkspacePath`, never a bare path.
- UI talks to the core only over `/api/v1` and the one WebSocket stream. `web/src/api/generated/` comes from `am-api` via ts-rs (`xtask gen-types`) — never hand-edit it.
- UI uses DESIGN.md tokens as CSS variables only — no literal colours or sizes, system font only, no remote fonts, images or scripts. Model output renders only through the sanitising Markdown renderer.
- `.agentic/` names the project's runtime folder, `~/Library/Application Support/agentic-manager-projects/<project-id>/` (AD-32, `project_id` in `company.yaml`); never write runtime state into the project folder. A seat's fetches match only its `allowed_hosts` through `am_domain::HostPattern`; Account calls go only to that Account's pinned endpoint (AD-48); runtime paths come only from `am_domain::RuntimeLayout`, and the only runtime file in a project is the `.agentic-open` marker; globs match only through the `am-glob` crate.
- Money is i64 micro-units (USD and the company currency, which defaults from the system locale; never hard-code a currency or timezone) with a rate-snapshot id; runtime ids are UUIDv7 text; times are UTC RFC 3339 with ms and `Z`; API JSON is camelCase, DB snake_case.
